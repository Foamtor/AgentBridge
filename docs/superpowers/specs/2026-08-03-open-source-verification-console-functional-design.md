# AgentBridge 开源验证工作台功能设计

> **状态：** 已确认（含本地管理员认证与桌面端约束）  
> **日期：** 2026-08-03  
> **前置输入：** [已确认用户故事板](../storyboards/2026-08-03-open-source-verification-console.md)  
> **当前阶段：** 功能与信息架构设计；不是视觉原型、实施 Spec 或任务 Plan

## 1. 产品决策

`apps/web` 的默认入口从“后台总览 / 通用调试页”调整为“需要管理员登录的开源验证工作台”。它服务于刚 clone 仓库的开发者，用仓库自带的 `work_order_ops` 在几分钟内证明平台能力；它仍是集成调试工具，不伪装成客户业务系统。

首轮体验遵循四层信息顺序：

1. **身份**：通过一次性管理员凭据登录并完成强制改密；三分钟业务验证目标从改密完成后开始计算；
2. **环境**：能否运行，演示边界是什么；
3. **场景**：要验证哪项能力；
4. **业务结果**：表格、图表、引用、草稿与创建结果；
5. **平台证据**：状态、工具调用、有序事件与运行标识。

高级参数、原始协议和管理功能全部保留，但不再争夺默认视线。

## 2. 范围

### 本次必须完成

- 默认 Compose 提供本地管理员登录；首次启动生成一次性初始密码且只向 API 日志输出一次。
- 首次登录必须设置符合安全策略的新密码，完成前不能进入控制台。
- `/` 成为登录后的验证工作台，默认验证 `work_order_ops`。
- 三个一键场景覆盖只读查询与图表、知识引用、审批写入。
- 业务结果与平台证据分区展示，并关联到同一个 run。
- 完整的运行、取消、等待审批、批准、拒绝、恢复、成功与失败状态。
- 统一的中英文切换，主流程不混用语言。
- 明确展示技术预览、脱敏模拟数据、离线模型/知识后端等真实运行边界。
- thread、route、Token、自定义 query、原始事件和并发冲突测试进入高级调试区。
- 现有管理页面保留为次级“管理”区域，并继续受原权限控制。
- 验证结束后引导到 `SKILL.md`、`_scaffold`、`work_order_ops` 和测试文档。

### 本次不做

- 客户业务前端、聊天产品或可视化工作流编辑器。
- 普通用户注册、邮件找回、社交登录、生产 IdP 配置向导或多租户用户管理。
- 通用 domain 市场、插件安装器或无代码业务建模。
- 在 Web 中编辑 prompt、tool 或 domain 源码。
- 为截图添加虚假的运行数据或生产能力声明。
- 重做现有后台各页面的内部功能；只调整其入口与导航归类。
- 移动端和触屏专用布局；首版仅支持桌面浏览器工作台。

## 3. 信息架构

```text
AgentBridge
├─ 登录 /login                     未登录入口
├─ 首次改密 /setup-password        受限会话唯一可访问页面
├─ 验证工作台 /                    登录后默认入口
│  ├─ 环境摘要
│  ├─ 场景选择
│  ├─ 运行工作区
│  │  ├─ 业务结果
│  │  └─ 技术证据
│  ├─ 高级调试
│  └─ 接入下一步
├─ 契约 /contracts                 登录后开发者参考
└─ 管理                             仅有管理权限时显示
   ├─ 总览 /admin
   ├─ 插件 /admin/domains
   ├─ 工具 /admin/tools
   ├─ 运行 /admin/runs
   ├─ 知识 /admin/knowledge
   ├─ Prompts /admin/prompts
   ├─ 配置 /admin/config
   └─ 用量 /admin/usage
```

路由调整原则：

- 除 `/login`、`/setup-password`、认证 API 和基础健康检查外，Web 页面与业务 API 默认要求已完成改密的管理员会话。
- 未登录访问 `/` 重定向到 `/login`；必须改密的会话重定向到 `/setup-password`。
- 旧 `/debug` 重定向到 `/?mode=advanced`，保留已有书签的可用性。
- 现有后台首页从 `/` 移到 `/admin`；其余后台路径统一增加 `/admin` 前缀。
- 旧后台路径在技术预览期做兼容重定向，避免突然失效。
- `/contracts` 登录后可访问。

## 4. 页面组成

### 4.1 登录页与首次改密

默认 Compose 使用 `AUTH_MODE=local`。首次初始化时：

1. API 在数据库中不存在管理员时创建唯一的本地 `admin` 账号；
2. 使用密码学安全随机数生成不少于 24 个字符的一次性初始密码；
3. 只保存 Argon2id 哈希和 `must_change_password=true`，不保存明文；
4. 明文密码只在首次创建时写入 API 容器标准错误一次，并明确标注取用命令；
5. API 重启不会再次输出或重新生成密码。

登录页只包含用户名、密码、显示密码切换、语言切换和环境不可用诊断。用户名首版固定为 `admin`，不提供公开注册。

初始凭据验证成功后，服务端只签发 15 分钟有效的受限改密会话。该会话只能调用身份状态、修改密码和退出接口；访问其他 API 一律返回稳定的 `password_change_required`，前端重定向到 `/setup-password`。

改密页显示新密码、确认密码、实时强度和逐项策略。改密成功必须在一个事务中：保存新 Argon2id 哈希、清除 `must_change_password`、使初始凭据与所有旧会话失效，再签发正常管理员会话。刷新、关闭页面或直接输入其他 URL 都不能绕过改密。

密码策略由服务端最终执行：

- 最少 12 个 Unicode 字符，最多 128 个字符；允许空格和长口令；
- 拒绝与用户名相同或包含完整用户名（忽略大小写）的密码；
- 拒绝仓库内离线常见/已泄露口令列表中的密码；不把用户密码发送给外部检测服务；
- 使用强度估算器要求至少达到 `strong`，前端使用同一规则做即时反馈，但不能代替服务端校验；
- 不强制大写、小写、数字、符号的机械组合，不静默截断，不定期强制轮换；
- 修改密码时必须与确认值一致，且不得等于当前密码。

管理员遗失初始密码或正式密码时，不提供默认密码、密保问题或邮件找回。操作员在 API 容器内执行显式恢复命令，命令轮换为新的随机一次性密码、撤销所有会话并将账号重新置为 `must_change_password=true`；新密码仍只输出一次。恢复命令必须记录安全审计，但不得记录密码明文。

登录失败统一显示“用户名或密码不正确”，不泄露账号状态。按账号与来源进行渐进式限速；成功登录后清理失败计数。首版不采用永久锁号，避免单一管理员被恶意锁死。

### 4.2 全局应用栏

固定提供：

- AgentBridge 产品名，点击回到验证工作台；
- 一级入口“验证”和“契约”；
- 有权限时显示“管理”；
- 全局语言切换 `中文 / English`；
- GitHub 仓库链接。

不在全局导航平铺全部后台页面。进入管理区域后再显示管理子导航。

应用栏右侧显示当前管理员和退出操作。退出后服务端撤销当前会话，浏览器清除 Cookie 并返回登录页。

### 4.3 环境摘要

页面加载后自动检查，不要求用户操作。显示：

- 总体状态：检查中、可以验证、部分降级、不可验证；
- API、检查点、事件日志、业务数据源的独立状态；
- 当前 LLM 与知识后端类型；
- 当前认证模式和演示租户；
- `work_order_ops` 是否已注册并可运行；
- “脱敏模拟数据”“离线/外部依赖”“技术预览”标签。

总体状态计算：

- 必需组件均正常且参考 domain 可用：`ready`；
- 可运行但可选知识能力不可用：`degraded`，禁用知识场景，其余可运行；
- API、数据源或参考 domain 不可用：`blocked`，所有主场景禁用。

失败时展示针对性恢复命令，例如查看 Compose 服务与 API 日志；诊断内容可展开，不占据正常状态下的首屏。

### 4.4 场景选择

三个固定的参考场景不是通用模板市场，而是首发验收路径：

| 场景 | 默认请求 | 证明的能力 | 写入 |
|------|----------|------------|------|
| 查询与分析 | `show work orders as a pie chart` | 租户数据查询、结构化表格、ECharts 图表 | 否 |
| 检索处理规范 | `search the work-order SOP` | 知识检索、引用来源、后端降级语义 | 否 |
| 创建工单 | 仓库内置的脱敏草稿参数 | 草稿冻结、审批、二次鉴权、事务和幂等 | 批准后才写入 |

每个场景显示一句目标、风险等级和依赖状态。选择场景只切换说明与预览；“运行场景”是唯一主操作，一次点击立即执行。

切换场景不会清除已完成结果；新运行开始时建立新的 thread，避免历史审批或上下文干扰验收。

### 4.5 运行工作区

工作区在未运行时提供有教学价值的空状态；运行后由同一个 run 驱动两个视图。

#### 业务结果

默认可见，按事件实际出现的顺序组织，但不逐条展示协议：

- 文本结论；
- 工单表格，包含空结果与截断状态；
- bar、line、pie 图表及可读数据降级；
- 知识引用列表，显示标题/来源，不伪造不存在的链接；
- 工单与台账草稿的字段化预览；
- 审批决策区；
- 创建成功摘要，显示工单号、台账号、处理人和状态。

业务事件没有对应渲染器时，显示“此结果需要新渲染器”，并允许在技术证据中查看原始 payload。

#### 技术证据

默认折叠摘要，展开后分为三层：

1. **运行摘要**：run、route、thread、租户、起止时间、终态、事件数；
2. **执行步骤**：start、工具调用/结果、审批等待/恢复、done/error 等人类可读步骤；
3. **原始事件**：按 `sequence` 排序，支持稳定事件/扩展事件过滤与 JSON 展开复制。

只展示后端实际返回或可信运行快照中的证据。前端不得通过解析未验证 JWT 来宣称权限已经生效。

### 4.6 审批决策区

出现 `x.bridge.approval_required` 后：

- 运行状态变为“等待审批”，明确“尚未写入”；
- 字段化展示被冻结的 work order、ledger 与 action；
- “批准”为明确的提交动作，“拒绝”为次级动作；
- 决策提交期间禁用重复操作；
- 返回 `succeeded` 时直接渲染响应中的持久化 result；
- 返回 `denied`、`expired`、策略拒绝或执行失败时显示对应终态和零写入语义；
- 网络状态不确定时通过审批查询恢复，不能把未知状态重置为待批准。

幂等证明不再使用首屏的“连点测 409”。在审批成功详情中提供“重新读取结果”，前后对比相同 ID 和审批状态；真正的并发冲突测试留在高级调试区。

### 4.7 接入下一步

当用户至少完成一个只读场景后出现轻量提示；完成审批场景后显示完整验收摘要：

- 已验证的能力和未执行的可选能力；
- 打开 `SKILL.md`；
- 查看 `_scaffold`；
- 查看 `work_order_ops`；
- 打开 AI Coding 指南与测试命令。

这些链接指向 GitHub 仓库中的稳定路径。Web 不尝试直接打开用户本机编辑器或修改源码。

### 4.8 高级调试

折叠区域保留专业开发者能力：

- 自定义 query；
- route 选择；
- thread ID 生成、查看与编辑；
- Bearer Token 设置；
- `extra` JSON 编辑与校验；
- 发送、取消；
- 同 thread 并发冲突测试；
- run 回放；
- 原始 HTTP/SSE 错误详情。

高级模式不得改变推荐场景的安全默认值。JSON 无效、route 为空或 thread 为空时在客户端阻止发送并说明字段错误。

## 5. 状态模型

### 5.1 身份状态

```text
checking_session
  ├─ anonymous -> authenticating
  │                 ├─ password_change_required
  │                 └─ authenticated
  ├─ password_change_required -> changing_password -> authenticated
  └─ authenticated -> logging_out -> anonymous
```

- 认证状态只以服务端会话查询为准，不通过客户端解码 Token 推断管理员权限。
- `401 unauthorized` 进入未登录状态；`403 password_change_required` 进入强制改密状态。
- 会话过期时保留当前页面的非敏感本地 UI 状态，但清除业务结果和原始事件，登录后不自动重放写操作。

### 5.2 页面状态

```text
bootstrapping
  ├─ ready
  ├─ degraded
  └─ blocked
```

环境重试只更新环境状态，不清除当前运行结果。

### 5.3 单次运行状态

```text
idle
  -> starting
  -> streaming
       ├─ waiting_approval
       │    ├─ deciding
       │    ├─ succeeded
       │    ├─ denied
       │    ├─ expired
       │    └─ failed
       ├─ cancelling -> cancelled
       ├─ succeeded
       └─ failed
```

状态由事件与审批 API 响应归约得出，不以 `fetch` Promise 结束简单等同于业务成功：

- 收到 `done` 才是普通成功；
- 收到 `error` 是失败；
- 收到 `cancelled` 是已取消；
- 收到 `approval_required` 后，即使初始 SSE 结束也保持等待审批；
- 浏览器断线但无终端事件时标记“状态待恢复”，不可显示成功。

### 5.4 结果保留

- 每次运行持有独立 `run_id/thread_id/events/result/status`。
- 当前会话保留最近三次运行，方便比较三个黄金场景；刷新后不承诺恢复列表。
- URL 带 `run_id` 时进入只读回放；不能在回放事件上重新审批。
- 新运行不会覆盖仍待审批的运行，用户必须先处理或明确离开该状态。

## 6. 数据与 API 设计

### 6.1 直接复用

| API / 契约 | 用途 |
|------------|------|
| `GET /ready` | 基础设施检查与 503 失败状态 |
| `POST /chat/stream` | 推荐场景与高级调试的 SSE 运行 |
| `POST /chat/cancel` | 取消当前 thread |
| `POST /approvals/{approval_id}` | 批准或拒绝并返回持久化结果 |
| `GET /runs/{run_id}/events` | run 回放与事件证据 |
| 稳定事件 + `x.work_order_ops.*` | 状态归约与业务结果渲染 |

### 6.2 新增本地管理员认证

认证属于 `apps/api` 宿主层，不进入 `packages/core` 或任何 domain。新增 PostgreSQL 表：

- `console_admins`：用户名、密码哈希、强制改密标志、密码版本、创建/修改时间；
- `console_sessions`：随机会话令牌的哈希、管理员、会话类型、过期时间、最后使用时间、撤销时间；
- `console_login_attempts`：限速所需的最小失败状态，可按保留期清理。

会话使用至少 256 bit 的不透明随机令牌。数据库只保存令牌哈希，浏览器只通过 `HttpOnly` Cookie 持有原始令牌；Cookie 使用 `SameSite=Lax`、限定 Path，不可被前端 JavaScript 读取，HTTPS 环境强制 `Secure`。正常会话默认 12 小时空闲过期、24 小时绝对过期；受限改密会话 15 分钟绝对过期。

新增接口：

| API | 行为 |
|-----|------|
| `GET /auth/session` | 返回 `anonymous`、`password_change_required` 或已完成改密的管理员安全投影 |
| `POST /auth/login` | 校验本地管理员凭据，设置受限或正常会话 Cookie |
| `POST /auth/change-password` | 仅受限/正常会话可用；校验当前凭据语义和新密码策略，轮换所有会话 |
| `POST /auth/logout` | 撤销当前会话并清除 Cookie，重复调用保持幂等 |

所有状态变更接口检查同源 `Origin` / `Sec-Fetch-Site`；部署在 HTTPS 时拒绝非安全会话配置。登录与改密响应使用 `Cache-Control: no-store`，密码不得进入 URL、日志、审计 payload 或错误详情。

`AUTH_MODE` 支持：

- `local`：默认 Compose，本地管理员 Cookie 会话；
- `oidc`：后续生产/企业接入，完成现有 PKCE 后使用外部 IdP，API 继续校验 JWT；
- `disabled`：仅显式测试环境允许，等价于当前开发管理员上下文，并在 UI 显示醒目不安全状态。

不能同时启用 `local` 与 `disabled`。旧 `AUTH_REQUIRED=false` 在迁移期仅映射到显式测试配置，默认 Compose 不再依赖无认证的 `dev` 超级管理员。无论身份来源如何，API 都将其映射为现有 `RunContext`，权限与租户规则保持不变。

新增容器内恢复命令，例如 `python -m auth.reset_console_admin`。该命令只能在服务端环境执行，要求明确确认目标账号，生成并输出新的一次性密码；不得提供远程匿名 reset API。

### 6.3 新增最小控制台引导快照

新增登录后可访问的 `GET /console/bootstrap`。它只返回非秘密、当前调用方可见的启动信息，不替代管理 API：

```json
{
  "release": {"version": "0.1.0", "stage": "technical_preview"},
  "runtime": {
    "llm_backend": "fake",
    "knowledge_backend": "fake",
    "auth_required": false
  },
  "context": {"tenant_id": "dev"},
  "reference": {
    "route": "work_order_ops",
    "available": true,
    "data_class": "synthetic_redacted",
    "capabilities": ["list", "chart", "citation", "approval_write"]
  }
}
```

约束：

- 不返回 DSN、密钥、完整配置、用户 Token 或未经权限过滤的工具清单。
- `available` 从已注册 domain catalog 计算，不写死为 `true`。
- `context` 来自认证后的 `RunContext`；无认证的 Compose 默认上下文必须与实际请求一致。
- capabilities 来自 app 侧 reference metadata，不在 `packages/core` 写入业务名。
- 环境摘要将此快照与 `/ready` 合并；任一失败都不得伪造“全部就绪”。

### 6.4 新增审批只读查询

新增 `GET /approvals/{approval_id}`，返回与决策响应一致的 `ApprovalPublic`：

- 按当前 `tenant_id` 隔离；跨租户表现为 404；
- 仅允许原请求人或具备 `approval:decide` / 管理读取权限的调用方；
- 不返回内部 lease、请求人完整权限快照或敏感 action 元数据；
- 用于网络恢复、刷新真实状态和幂等结果复读，绝不触发执行。

### 6.5 前端归约模型

前端不直接让组件各自扫描事件。统一 reducer 输出：

```ts
type VerificationRun = {
  scenarioId: "analysis" | "knowledge" | "approval" | "custom";
  runId?: string;
  threadId: string;
  route: string;
  status: RunStatus;
  events: StreamEvent[];
  results: BusinessResult[];
  approval?: ApprovalView;
  error?: SafeError;
};
```

事件先按 `sequence` 去重与排序，再归约成状态和业务结果。未知事件保留在证据视图，不影响主流程。

## 7. 中英文设计

- 采用全局 locale 状态，初始值优先读取用户持久化选择，其次浏览器语言，最终回退英文。
- 所有导航、按钮、状态、错误、空状态、表头与辅助文案进入同一资源系统。
- API 返回的代码标识通过映射显示本地化名称，同时在技术证据中保留原值。
- 后端英文错误不直接作为主错误文案；前端按 HTTP 状态和 `detail.code` 映射安全文案，原始错误仅在诊断详情中显示。
- 演示业务数据本身若为中文，不因切换英文而伪造翻译；界面需标注“sample data content is not localized”。后续如 migration 提供双语种子，再单独升级。

## 8. 权限与安全

- 默认 Compose 不再以无认证 `dev` 超级管理员暴露控制台；健康检查只返回最小存活/就绪信息。
- 密码使用 Argon2id 参数化哈希；实现时按运行环境基准选择参数，并设置最低安全参数，哈希记录携带算法版本以支持登录时 rehash。
- 初始密码使用系统 CSPRNG 独立生成，不来自镜像、仓库、环境变量默认值或数据库密码。
- 初始密码只输出一次；日志聚合属于敏感运维边界，README 要求完成改密后清理或限制日志访问。
- 正常会话、受限改密会话和 OIDC Token 不写入 `localStorage`。
- 登录、失败限速、改密、重置与退出写安全审计；不得记录密码、Cookie 或密码哈希。
- 未授权工具列表仍由后端 Policy 过滤；Web 只展示实际证据，不自行推断可调用能力。
- 高级调试的手动 Bearer 仅在显式 OIDC/开发调试模式显示；默认本地认证不把会话转换为可复制 Token。
- 审批按钮必须依赖真实 `approval_id` 和待决状态；回放模式、过期状态和未知状态下不可执行。
- 输出中的 JSON 一律作为数据渲染，不执行函数、HTML 或脚本；ECharts option 沿用纯 JSON 限制。
- 错误摘要不得暴露服务器堆栈、DSN 或 Token；技术详情也只显示 API 已返回的安全错误。
- 新 API 遵守租户隔离与现有认证中间件，不创建开发模式后门。

## 9. 桌面布局与可访问性

- 首版只设计桌面浏览器体验，目标内容宽度为 1024px 至 1600px，不提供移动端断点或触屏专用交互。
- 主工作区可并列呈现场景导航与结果；技术证据是同级可展开区域，不采用卡片套卡片。
- 浏览器窗口小于 1024px 时保持结构稳定，允许页面横向滚动并提示使用更宽的桌面窗口；不隐藏关键功能，也不重排成移动布局。
- 所有状态都有文本和图标，不仅依赖颜色。
- 场景选择使用可键盘操作的单选/分段语义；业务结果表格支持横向滚动并保持表头可识别。
- 运行中使用 `aria-live=polite` 汇报阶段变化；错误和审批结果获得合适的 live region。
- 图表同时提供可访问名称和数据表/列表降级。
- 动画仅用于状态过渡，并遵守 `prefers-reduced-motion`。

## 10. 视觉方向约束（供原型阶段）

- light-first、克制、精确、工具化；不做营销 Hero。
- 使用紧凑应用栏、清晰的内容轨道和较少的有边界区域。
- 页面不采用等尺寸指标卡网格，不嵌套卡片，不使用玻璃、霓虹、渐变文字或装饰性 AI 图像。
- 语义色只服务于就绪、运行、等待、成功、警告和失败。
- 技术标识使用等宽字体；正文与标题使用可读的人文无衬线字体，不能整页“代码化”。
- 最值得记住的体验不是装饰，而是同一次 run 中“业务结果 / 平台证据”可清楚切换和互相定位。

## 11. 验收标准

### 管理员认证

- 新数据库首次启动只创建一个 `admin`，每个安装的初始密码随机且仅在首次创建日志出现一次。
- 数据库、配置、API 和 Web 均无法读取初始密码明文；API 重启不会再次显示。
- 初始登录后只能进入改密页；直接访问或调用其他受保护资源被拒绝。
- 弱密码、常见口令、包含用户名、超长输入、确认不一致和复用当前密码均由服务端拒绝并返回稳定错误码。
- 改密成功后初始凭据和全部旧会话失效，新 Argon2id 哈希可验证但不可逆。
- 登录失败不区分账号不存在与密码错误，连续失败触发渐进限速。
- Cookie 具有 `HttpOnly`、`SameSite` 和正确的 `Secure` 行为；状态变更接口拒绝跨站请求。
- 退出、会话空闲过期和绝对过期后，受保护 API 返回 401。
- 容器内恢复命令可轮换一次性密码、撤销会话并强制再次改密，且不提供匿名远程重置。
- `AUTH_MODE=oidc` 与 `AUTH_MODE=disabled` 的边界清楚，disabled 不允许作为默认 Compose 或生产配置。

### 首次验证

- 未登录访问 `/` 进入登录页；完成管理员改密后才能看到验证工作台。
- 环境检查能区分 ready、degraded 和 blocked，且声明与真实后端配置一致。
- “查询与分析”单击一次即可产生表格和图表，默认 route 不是 `echo`。
- 知识场景能显示 citation；知识后端不可用时只禁用或降级该场景。
- 业务结果默认不被原始事件淹没，所有事件仍可在技术证据中找到。

### 审批闭环

- 草稿阶段明确显示尚未写入；批准前无 created 结果。
- 批准、拒绝、过期、权限拒绝、执行失败有不同终态。
- 批准成功直接显示工单号与台账号，不只显示审批状态字符串。
- 网络状态不确定时可通过 GET 恢复，不通过重复 POST 猜测。
- 重读成功审批返回相同结果，前端不产生第二次业务动作。

### 开发者工具质量

- 中英文任一语言能走完整主流程，核心导航和操作不混用语言。
- thread、route、Token、extra 与 409 测试默认折叠，但仍可操作。
- run 回放只读且能重建业务结果与技术证据。
- 管理入口只对管理员显示，旧路径有兼容行为。
- 在 1024px、1280px、1440px 和 1600px 桌面视口下无文字遮挡、意外控件溢出或关键功能消失。

## 12. 原型阶段需要覆盖的画面

HTML 原型至少可交互切换以下状态：

1. 管理员登录与错误/限速状态；
2. 首次登录强制改密与强度反馈；
3. 环境就绪的默认首页；
4. 查询与分析运行中；
5. 表格/图表成功及技术证据展开；
6. 知识引用结果；
7. 写操作草稿与等待审批；
8. 批准成功及幂等结果复读；
9. 环境 blocked 或运行失败；
10. 高级调试展开；
11. 中文与英文；
12. 1024px、1280px、1440px 和 1600px 桌面布局。

原型使用固定模拟数据展示交互和信息层级，不接真实 API，也不作为最终代码复用。原型确认后才形成实施 Spec。

## 13. 阶段门
