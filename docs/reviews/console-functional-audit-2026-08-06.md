# AgentBridge 控制台功能审阅与优化措施

日期：2026-08-06
范围：`apps/web` 全部路由及其直接依赖的 API、存储和运行时接线
审阅方式：本地开发服务实测登录页；其余受保护页面通过前端组件、API 路由、适配器、迁移和测试交叉核对。由于当前 `5175` 会话未登录，未把受保护页面的代码推断描述成浏览器实测。

## 1. 结论

当前控制台已经具备一个可信的开发者工具外形，验证工作台、插件调试场、模型配置、源码插件目录和运行配置也有真实能力支撑。但它还不能被评价为“所有管理功能都已闭环”。核心问题不是视觉，而是部分页面的承诺大于实现：

1. **真实模型首选别名存在错误路径。** 验证工作台的模型状态初始为 `default`，加载模型后没有同步为第一个真实别名；用户切到“真实模型”直接运行时，仍可能发送 `default`。
2. **验证结果不是验收结果。** 页面把收到 `done` 当作完成，却没有逐项核对场景承诺的列表、图表、引用、审批和幂等证据。
3. **审批写入没有在页面完成闭环。** 批准后只显示审批状态，不重新读取运行事件和数据库写入结果，用户看不到“只创建一次”的证据。
4. **模型“可用”只代表凭据能解密并创建客户端，不代表远端 API 可连通、模型名正确或真实调用成功。**
5. **提示词和 Token 用量页面目前是误导性功能。** 提示词存储在内存中，运行时没有业务消费点；Token 用量同样存内存，生产调用路径没有写入记录。
6. **知识页只是原始状态 JSON。** 它没有完成“配置后端 -> 健康检查 -> 导入/确认数据 -> 发起检索 -> 查看引用”的开发者任务。
7. **工具权限矩阵可能给出错误结论。** 矩阵只用角色、不给权限构造上下文；同名工具还会互相覆盖，且页面漏掉 `required_permissions_all`。
8. **“数据库而非内存”的产品约束尚未全面落实。** Compose 已将业务数据、审批、运行证据、配置、模型配置和 checkpoint 放入 PostgreSQL，但审计、提示词、Token 用量、摄取任务仍固定使用内存适配器。

因此，当前状态适合作为“核心运行链路的技术预览”，不适合把所有管理菜单都宣称为可用于实际项目的完整后台。建议先修 P0 的真实性和闭环，再优化页面密度与美观。

## 2. 两类用户的核心任务

| 用户 | 首要任务 | 成功标准 |
|---|---|---|
| 第一次使用者 | 登录、确认环境、运行 Fake 案例、看懂业务结果和平台处理 | 3 分钟内知道数据是演示数据、运行成功在哪里、平台替他做了什么、下一步如何接真实模型 |
| 实际项目开发者 | 接模型、接数据/知识、加载插件、调工具和权限、复现失败、验证审批与审计 | 每个配置都有测试动作；每次运行可追溯；页面状态来自数据库；失败能定位并给出下一步 |

控制台的信息架构应围绕四段旅程，而不是围绕 API 名称：

1. **先验证平台**：登录 -> 环境检查 -> Fake 黄金路径 -> 看结果与证据。
2. **再接入依赖**：模型 -> 数据源/知识 -> 连接测试 -> 真实案例。
3. **再开发插件**：插件加载状态 -> 工具/权限 -> 调试场 -> 运行详情。
4. **最后治理运行**：失败运行 -> 标注 -> 用量 -> 审计 -> 配置变更记录。

## 3. 跨页面系统问题

### P0：真实性与闭环

| 问题 | 用户影响 | 代码级措施 |
|---|---|---|
| 真实模型默认别名未同步 | 用户选了“真实模型”却可能仍走 `default` | `/models` 加载完成后将选择值设为首个可用 alias；切换 real 时再次校正；后端在 `case_mode=real` 且 alias 不是真实模型时返回明确 409，禁止静默回退 |
| 场景完成只依据 `done` | “完成”不等于“符合预期” | 建立场景断言器：列表事件、图表 option、citation、approval、created、重复审批结果分别形成 pass/fail；报告同时展示预期、实际、证据事件 |
| 审批后不回读事件 | 看不到真实写入和幂等结果 | 审批 API 返回 `run_id`、执行结果和新增事件序号；前端批准后轮询/回读 `/runs/{id}/events`，更新 reducer 和业务展示；增加重复批准的幂等断言 |
| 模型“可用”含义错误 | 无法判断 API/key/model 是否真的正确 | 新增 `POST /admin/models/{alias}/test`，执行最小请求并返回延迟、模型响应标识和脱敏错误；状态拆成“已加载 / 最近测试成功 / 测试失败” |
| Prompt 管理未持久化、未接运行时 | 保存和发布没有实际业务价值 | 在 PostgreSQL 增加 prompt、version、published_version 表；实现 PromptStore Port；在 domain 组装时注入 `PromptRegistry`，真实 graph 必须通过该 Port 读取；完成前隐藏菜单或标记“实验性、重启丢失且未接业务” |
| 用量没有生产数据 | 页面永远空或重启丢失 | 在 LLM Gateway 返回中统一投影 usage，随 `run_id/tenant/route/model` 写 PostgreSQL；页面只展示数据库聚合，移除固定 `MemoryUsageStore` 生产接线 |
| 审计仍在内存 | 平台声称审计但重启即丢 | 增加 PostgreSQL AuditLogger，Compose 默认使用；保留 memory 仅测试；管理中心增加审计检索/导出入口 |
| 知识接入无操作闭环 | 用户不能证明 RAG-Agent/pgvector 真能用 | 知识页增加后端状态、只读/可写能力、连接测试、导入任务、测试检索与引用；摄取任务存 PostgreSQL；`rag_agent_pg` 明确只读并给出调试入口 |

### P1：信息架构与错误恢复

- 为所有管理子页增加“管理中心 / 当前页面”返回路径；当前顶栏只保留“验证、调试、管理”，契约放入管理或帮助入口。
- 建立统一的 API 错误模型，将 `401/403/409/422/503` 映射为用户能执行的下一步；不要显示 `Request failed (HTTP 422)`、`blocked_by_base_r_b_status_api`、`thread_busy` 等裸编码。
- 管理 API 的 `401` 应刷新会话并跳登录，`403` 应进入真正可达的无权限页；当前 `ForbiddenPage` 基本没有被请求层使用。
- 所有空态区分“没有数据”“能力未启用”“后端不可用”“没有权限”，并提供一个可执行入口。
- 所有页面完成中英文文案。当前工具、运行、提示词、用量、知识、契约及环境摘要仍混用中英文和内部字段名。
- 将“是否已配置”“当前生效值”“数据来源”“需要重启”“最近验证结果”做成统一状态模型，避免各页自行解释。

### P2：视觉、可访问性与一致性

- 当前克制、浅色、编辑式工具风格符合品牌，不像常见的渐变、玻璃、卡片堆叠式 AI 页面，应保留。
- 页面标题仍为 `AgentBridge Debug`，应改为 `AgentBridge Console`，并按路由更新文档标题。
- 登录页实测主按钮高度约 45px，焦点样式清楚；但密码输入缺 `autocomplete="current-password"`，错误与帮助文案缺 `aria-describedby`。
- 未登录和首次改密页面没有语言切换，违反“全局语言选择”的设计原则。
- 顶栏语言/退出按钮点击区域偏小；刷新按钮使用字符图标，应统一为现有图标库或 Lucide，并保留 tooltip。
- CSS 已明确桌面最小宽度 1024px；这与产品约束一致，不应为本次审阅强行改成移动布局。仍应验证 1024、1280、1440 三个桌面宽度的文本溢出。
- 颜色多数使用 token，但后续样式存在大量硬编码状态色；应收敛为 `success/warning/error/info/surface` 语义 token。

## 4. 逐页功能审阅

### 4.1 登录 `/login`

**用户目的**：拿初始密码首次进入，或用已设置密码再次登录；失败时知道是密码、限速、代理还是 API 问题。

**当前实现**：用户名固定 `admin`；能区分 401、429、同源失败和服务不可用；页面明确初始密码只用于首次登录。浏览器实测布局克制、层级清晰、表单标签完整。

**缺口**：提交没有 loading/防重复；未登录时无法切换语言；帮助只说“API 容器日志”，不适合源码开发启动；429 不展示可重试时间；密码框没有自动完成语义；页面标题仍是 Debug。

**优化**：增加 `submitting` 状态、禁用按钮和 `aria-busy`；帮助改为“API 启动日志”，按部署模式补充命令；后端返回 `Retry-After` 并在页面倒计时；在认证壳层保留语言切换；错误绑定到密码输入。实现集中在 `LoginPage.tsx`、`session.tsx`、认证 API 错误投影和 `index.html`。

### 4.2 首次改密 `/setup-password`

**用户目的**：用一次性密码设置长期密码，确认规则并进入工作台。

**当前实现**：8 位以上且含字母和数字，前后端均校验；保存后初始密码失效；强制改密会话不能访问其他页面。

**缺口**：后端错误直接显示内部 code；没有提交状态；没有逐条显示“长度/字母/数字/两次一致”；无显示密码按钮和语言入口；输入未声明合适的 autocomplete。

**优化**：规则清单实时显示通过状态；错误映射为“当前一次性密码错误/已过期/会话失效/新密码不合规”；提交期间禁用；新密码使用 `new-password`；保留返回登录和语言切换。代码集中在 `ChangePasswordPage.tsx` 和认证错误映射。

### 4.3 验证工作台 `/`

**用户目的**：第一次运行黄金案例，确认业务结果、真实/Fake 边界、模型/数据来源、工具调用、SSE、审批和持久化。

**当前实现**：四个场景卡片已有“问题/预期”；Fake 与真实模式分开；业务回复、工具、流程、结构化结果、原始 SSE 分区；环境摘要显示租户、数据类别和存储；真实模型列表来自服务端。

**闭环判断**：Fake 读/图/知识展示基本闭环；真实模型、期望验收和审批写入尚未闭环。

**关键问题**：

- `useVerificationRun` 的 model 初始为 `default`，模型加载后不更新。
- 没有模型时“真实模型”按钮被禁用，而“去模型管理”链接只在已经进入 real 模式时出现，用户无法从死路进入配置。
- 报告中的“问题”显示英文内部 query，而场景卡显示中文业务问题，前后不一致。
- “完成”只代表收到 `done`，没有验证结构化事件是否符合预期。
- 批准后不重新读取事件，创建结果和幂等性不可见。
- 环境摘要混用 `real ready`、`checks`、`synthetic_redacted` 等内部文本，且只给检查数量，不告诉用户哪项失败。
- SSE 区没有复制、下载、事件筛选、时间和人类可读说明。

**优化**：将页面改成“准备状态 -> 场景 -> 运行报告”三段；无模型时真实模式仍可点，点击后显示缺失项和“配置模型”；报告固定展示场景业务问题、实际发送内容可折叠；每个预期生成断言行；审批后自动补取事件；SSE 增加稳定/扩展筛选、复制、JSONL 下载、时间间隔。主要改动在 `VerificationWorkbench.tsx`、`useVerificationRun.ts`、`VerificationReport.tsx`、`GoldenCasePanel.tsx`、`EnvironmentSummary.tsx` 和对应 API。

### 4.4 插件调试场 `/playground`

**用户目的**：连续调自己的插件；选择插件和模型；构造请求；看回复、结构化扩展、工具、耗时、契约、原始事件；复现、导出和标注问题。

**当前实现**：这是当前最完整的页面。它有会话/运行历史、搜索和状态筛选、实时 SSE、取消、同会话重复发送验证、请求回放、curl、环境摘要、运行诊断、工具参数与结果、契约断言、JSONL 导出、数据库标注。

**缺口**：

- 初始 `echo + default + hello` 仍偏内部示例；没有明确“default 是 Fake 还是环境模型”。
- 四个初始化请求用 `Promise.all`，任一管理接口失败会让路由、模型、历史一起失败。
- 历史只取前 100 条再在浏览器筛选；深链到更老 run 无法打开，也没有提示。
- “复制 curl”没有携带本地 HttpOnly 会话，也没有可替代的 API token，命令在默认本地认证下通常不能直接运行。
- 错误仍显示 HTTP/code；请求成功提示和错误同时可能留在状态条。
- 业务结构化渲染只特判 `work_order_ops`，自定义插件没有前端 renderer 注册机制。
- 审批复用同一个未回读结果的 `GoldenCasePanel`。

**优化**：各数据源独立加载和降级；筛选改为服务端分页并支持 run_id 直查；curl 生成器明确认证方式，默认给出可执行的“获取开发 token/使用反代会话”方案；引入前端 `DomainRendererRegistry`，插件可选注册扩展事件渲染器但不改 core；错误使用统一投影；审批后刷新。实现涉及 `PluginPlayground.tsx`、`api.ts`、`HistoryRail.tsx`、`RequestComposer.tsx` 和 run 查询 API。

### 4.5 管理中心 `/admin`

**用户目的**：知道现在什么可用、什么需要处理，并进入下一项配置或排障。

**当前实现**：已经按“先配置/业务接入/运行治理”分组；能展示插件数量、24h 运行、模型和基础设施；失败运行可跳调试场。这比早期空管理页明显更合理。

**缺口**：模型状态只检查环境变量中的 API key，可能忽略数据库模型，导致模型页已配置、总览仍显示降级；基础设施只显示总状态，不能展开失败原因；没有审计入口；没有首次接入进度；所有链接视觉权重接近。

**优化**：总览 API 使用 `model_config_service.has_real_model` 和最近连接测试结果；显示“模型/数据/知识/持久化/插件”五项接入清单；异常项排在最前并直接跳到解决动作；基础设施可展开具体检查；增加审计入口。实现集中在 `admin_overview.py` 和 `OverviewPage.tsx`。

### 4.6 业务插件 `/domains`

**用户目的**：确认源码插件是否被发现、图和工具是否注册、需要哪些依赖/权限，随后去调试。

**当前实现**：页面已经明确“插件在源码中创建和修改”，因此只读不是问题；能显示工具详情、任一/全部权限、审批动作，并跳到对应 route 的调试和工具页。

**缺口**：`graph_registered` 只说明注册，不说明模型、数据源、知识和审批存储是否可用；插件来源由前端按名字猜测；无加载失败信息、代码路径、版本、刷新和依赖检查；工具 docstring 常为英文，中文界面会混排。

**优化**：domain 元数据增加 `source_kind/source_path/version/capabilities/dependencies`；启动时保存每个插件的加载诊断；页面区分“已发现/已注册/可运行/依赖缺失”；增加刷新状态和“创建插件”文档链接。仍保持源码型只读，不在网页中生成或修改 domain。

### 4.7 模型管理 `/models`

**用户目的**：安全配置 API 地址、Key、模型名；确认保存与加密；测试连接；启停、切换和删除。

**当前实现**：API Key 仅提交不回显；数据库存 Fernet 密文；加密主密钥写挂载 `.env` 而非数据库；可随机生成；创建、编辑、启停和删除会刷新运行时 alias。

**缺口**：没有连接测试；“可用”仅表示能解密并构建客户端；表单错误只显示 HTTP 状态；没有 Provider 预设、超时或自定义 header；删除使用浏览器原生 confirm；Key 生成后一直明文显示且没有复制/已备份确认；总览状态与该页可能不一致。

**优化**：增加“保存并测试”和列表内“测试连接”；状态显示最近测试时间、延迟、脱敏错误；常用 OpenAI-compatible provider 只提供 URL 预设，不把 provider 逻辑写入 core；编辑 Key、删除和首次写加密主密钥继续二次验证；使用应用内确认区而非原生 confirm；提供复制、显示/隐藏和备份确认。后端新增 test endpoint，不保存测试回复或明文密钥。

### 4.8 平台配置 `/config`

**用户目的**：安全修改可热更新参数，知道哪些参数来自数据库、哪些必须在部署层改，以及改动是否立即生效。

**当前实现**：目前两项热配置可写 PostgreSQL并立即更新运行时；每次保存二次验证当前密码；安全配置只显示是否已配置，不回显秘密。总体方向正确。

**缺口**：A/B/C 档位是内部术语；后端 description 固定中文，切英文后仍会混排；不能清除数据库覆盖恢复部署默认；没有 dirty 状态、变更前后值和审计入口；OIDC 模式不支持当前密码二次验证，但页面仍显示密码表单；布尔值显示 `true/false`。

**优化**：把档位翻译为“在线可改/重启生效/敏感项”；API 返回 description key 而不是中文；增加“恢复部署默认值”；保存前只对改动项启用按钮并显示前后差异；根据认证模式选择本地密码或外部重新认证。代码层可在现有 ConfigProvider Port 上扩展 `delete/reset`，无需改 domain。

### 4.9 工具与权限 `/tools`

**用户目的**：确认模型能看到哪些工具、当前身份能否调用、工具参数是什么，并安全试调只读工具。

**当前实现**：后端确实枚举真实工具并在调用前后做策略检查和审计；试调默认关闭；可按插件过滤。

**缺口**：

- 矩阵用“只有角色、没有权限”的模拟上下文，因此对依赖 permission 的工具会显示错误 deny。
- 矩阵以 tool name 为键，同名跨 domain 会覆盖。
- API/UI 漏掉 `required_permissions_all`，与插件页信息不一致。
- 列表不展示已有 description，也没有参数 JSON Schema；用户只能猜 arguments。
- 选择按钮在试调关闭时仍可选，之后才看到禁用说明。
- 直接工具调用可能有副作用，页面没有风险级别、租户上下文、确认或示例参数。

**优化**：矩阵改为后端返回“规则表达式”，不要伪造角色结果；若需要角色矩阵，必须由实际 policy bundle 生成完整 roles+permissions claims；键使用 `domain:name`；统一返回 any/all permission；从 LangChain/Pydantic tool schema 投影表单和示例；写工具默认禁止直接试调，只允许通过审批链路。先加后端正确性测试，再改 UI。

### 4.10 运行记录 `/runs`

**用户目的**：按状态、插件、时间、会话、追踪号找运行，快速定位失败并进入详情。

**当前实现**：API 支持状态、route、thread、trace、时间和 cursor；页面只使用状态、route 和前 20 条，并可跳调试场。

**缺口**：页面以自由文本输入状态和 route，每次按键都请求；不使用分页、时间、thread、trace；没有刷新、持续时间、模型、错误摘要；字段名全是内部英文；空态没有“去调试”。它与调试场历史重复但更弱。

**优化**：优先合并到调试场：顶栏“运行记录”直接打开 `/playground?view=history`。若保留独立页，使用状态分段控件、route 下拉、日期范围、服务端分页、刷新和失败摘要；点击整行进入详情。不要维护两个不同能力的运行浏览器。

### 4.11 提示词 `/prompts`

**用户目的**：查看插件默认提示词，创建平台覆盖，比较草稿与已发布版本，预览变量渲染，发布并验证真实运行使用了哪个版本。

**当前实现**：有草稿保存和发布 API，但页面只提供带默认示例内容的自由输入框；已登记列表不能点击加载。

**闭环判断**：未达成。生产接线使用 `MemoryPromptRegistry`；`prompt_runtime` 没有被任何 domain/graph 消费；重启丢失，发布也不会改变现有案例行为。

**优化**：在持久化和运行时消费完成前，从管理中心隐藏该入口或明确标为未实现。完整实现应包括 PostgreSQL 版本表、默认文件来源、草稿/发布差异、变量 schema、服务端安全预览、发布二次确认、回滚、运行记录中的 prompt name/version 证据。页面左侧列表选择，右侧编辑，不预填可误发布的 `demo_prompt`。

### 4.12 Token 用量 `/usage`

**用户目的**：知道哪个租户、插件和模型消耗多少 Token，定位异常并估算成本。

**当前实现**：只有内存聚合器和简单表格；生产路径没有调用 `usage_store.record`。

**闭环判断**：未达成。当前空态不能证明“没有用量”，只能说明“没有被记录”。

**优化**：先在 Gateway/生命周期统一采集 OpenAI-compatible usage 并写 PostgreSQL；不支持 usage 的模型显式标记 unknown；API 增加按时间桶、route/model/tenant 的稳定 schema；页面提供时间范围、汇总、输入/输出拆分和 CSV 导出。成本估算必须使用用户配置的价格表并标注估算，v0.1 可暂不做。

### 4.13 知识 `/knowledge`

**用户目的**：选择并确认知识后端，检查 embedding/数据库/RAG-Agent 连接，导入数据或确认只读来源，发起检索并查看引用。

**当前实现**：后端能返回 fake、langchain_pg、external、rag_agent_pg 的状态；已有 `/ingest`；页面只原样打印 JSON。

**闭环判断**：未达成。

**优化**：页面分成“连接状态、数据状态、测试检索”三段；把 backend、health、embedding、最近任务转换成人话；支持导入的后端提供文本/JSON 文档导入和任务进度；`rag_agent_pg` 显示“只读，数据由 RAG-Agent 管理”；增加 tenant-scoped 测试检索 API，返回 hits、score、source 并可一键去调试场运行 `work_order_ops` 知识场景。摄取任务从 MemoryIngestJobStore 改为 PostgreSQL。

### 4.14 事件契约 `/contracts`

**用户目的**：开发插件时理解稳定事件、扩展事件、字段约束和取消语义，并复制可运行示例。

**当前实现**：列出 9 类稳定事件、扩展命名规则和取消边界。

**缺口**：只是静态名称列表；没有字段、示例、必填项、版本、schema 下载、验证器入口；`docs/contracts.md` 不是链接；只支持中文；“默认折叠”描述与不同页面实际展示容易混淆。

**优化**：从单一协议 schema 生成页面与文档；每类事件可展开字段和示例；提供复制 JSON、下载 JSON Schema、粘贴事件验证；显示当前协议版本和兼容策略。它应是开发者参考页，不需要做成业务卡片。

### 4.15 无权限 `/forbidden`

**用户目的**：知道缺什么权限、哪个操作被拒绝、如何返回或切换身份。

**当前实现**：有简短错误和返回 `/` 的链接。

**缺口**：请求层不会统一导航到该页；“返回总览”实际返回验证工作台；不显示请求资源和需要的权限；没有退出/重新登录。

**优化**：`adminFetch/playgroundFetch` 统一处理 403，传入资源和稳定 permission code；页面显示“你可以做什么”，提供返回管理、返回验证、退出登录。不要显示策略内部堆栈或敏感详情。

### 4.16 OIDC 回调 `/auth/callback`

**用户目的**：使用 Authentik/OIDC 完成 PKCE 登录并回到原页面。

**当前实现**：仅为占位文本，没有交换 code、校验 state/verifier、建立会话或错误恢复。

**闭环判断**：未达成。默认 local auth 不受影响，但可选 Authentik profile 不能仅凭这个页面宣称控制台 OIDC 已完成。

**优化**：二选一：v0.1 明确隐藏/标注“API 可接 OIDC，控制台登录流未提供”；或完整实现 authorize -> callback -> token/session -> return URL，并覆盖 state 不匹配、用户取消、过期和权限不足测试。

## 6. TDD 验收标准

后续实现应遵循先失败测试、再最小实现、最后浏览器验证：

1. **真实模型**：配置两个 alias，进入工作台不手动改下拉，断言请求使用第一个真实 alias；远端测试失败时不得显示“可用”。
2. **场景验证**：只有 `done`、没有目标扩展事件时断言结果为失败；每个场景有独立 pass/fail 测试。
3. **审批**：批准后页面出现 created 事件；重复批准不增加 work_order/ledger 行数；刷新后证据仍存在。
4. **持久化**：重启 API 后 Prompt、Usage、Audit、IngestJob、Run、Annotation 均可读；生产 Compose 不接 Memory 实现。
5. **Prompt 生效**：发布版本后新 run 记录该版本并改变可观察输出；草稿不影响运行；回滚可验证。
6. **用量**：真实模型返回 usage 后数据库有 run-scoped 记录，聚合结果与原始记录一致；无 usage 明确为 unknown。
7. **工具权限**：any/all permissions、同名跨 domain、无权限不进入模型列表、调用时二次拒绝均有测试。
8. **知识**：RAG-Agent/pgvector 连接失败、只读、可摄取、跨租户隔离和 citation 投影分别有测试。
9. **UX**：每个页面至少覆盖 loading、empty、success、error、forbidden；中英文测试不得出现另一语言的主流程文案。

## 7. 应保留的优点

- 验证工作台和调试场明确区分业务结果与平台证据，方向正确。
- Fake 与真实模型没有被视觉上混为一谈，Fake 仍可离线演示。
- 模型 API Key 的“主密钥不入库、凭据密文入 PostgreSQL”边界合理。
- 平台配置采用二次验证、秘密不回显、热配置与部署配置分层，适合继续扩展。
- 插件页坚持源码型框架定位，没有误导用户在网页里搭业务系统。
- 调试场已有持久运行记录、工具链路、契约断言、JSONL 和 badcase 标注，是最值得作为其他管理页质量基线的实现。
