下面这些词会在文档和代码里反复出现。先混个脸熟即可，不用一次背完。

| 词 | 白话 |
|----|------|
| **业务插件（domain）** | 一块业务能力，通常是 `apps/api/domains/<名字>/` 一个文件夹。像卡带，插到主机上用。（目录名仍叫 `domains`，是历史叫法。） |
| **route** | 请求里写的名字，告诉服务「这次用哪个插件」。例如 `"route":"echo"`。 |
| **thread_id** | 会话编号。同一段对话用同一个 id，方便接着聊、也方便平台管「别抢跑」。 |
| **图（graph）** | 这个插件里「先干什么、后干什么」的流程编排（本项目用 LangGraph）。 |
| **Port（接口约定）** | 平台规定「检索 / 数据库该长什么样」；具体用 Postgres 还是外部 HTTP，用**适配器**接上。业务只依赖约定，不绑死某家实现。 |
| **适配器（adapter）** | Port 的具体实现。只在服务启动组装处创建，业务流程里不要直接 new。 |
| **SSE** | 服务器持续推送消息的方式，用来做流式对话（一边想一边往外吐）。 |
| **租户（tenant）** | 多客户隔离用的身份空间。知识检索等会按租户过滤，避免串数据。 |
| **开发者控制台** | 本仓库的 `apps/web`：给集成方做黄金验证、插件调试和实例管理，**不是**最终用户的业务 App。 |

## 一次请求大概怎样走

```text
你的客户端（或调试页）
   →  POST /chat/stream
      （带上：说什么 query、哪个会话 thread_id、用哪个插件 route）
   →  底座找到对应插件，按它的图往下跑
   →  需要时调工具 / 调模型
   →  用 SSE 推事件：常见会看到 `start` →（`text_delta` / 工具相关…）→ `done`
```

（具体字段以 [contracts.md](../contracts.md) 为准；`echo` 至少会有文本类事件和结束。）  
代码怎么分层：[architecture.md](../architecture.md)。

## 写代码时最常踩的几条

完整五条见 [AGENTS.md](../../AGENTS.md)。入门先记住：

1. 核心库 `application` 不要直接 import `adapters`；`domains/` 也不要 import 适配器实现来自己创建  
2. 核心库里不要写死某个业务插件名字  
3. 适配器「创建并接到应用」只在组装根（`lifespan`）；测例里注入假实现可以  
4. 调用方不具备权限的工具：不要进模型可见列表，**调用时还要再鉴权一次**  
5. 业务插件里不要自己拿着事件发送对象乱推（走 `OUTBOUND_EXTENSIONS_KEY`）
